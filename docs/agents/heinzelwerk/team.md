# Team rules

How heinzelwerk agents work in this repo. Mode rules (single repo vs workspace) live in the `heinzelwerk:team-modes` skill. This file holds only what is specific to this repo.

- **Autonomy**: full. Agents merge and apply on their own; breakages are learnings. Secrets are never published (name the variable, never the value), and the gate never merges its own policy.
- **Backend paths**: whole repo (`src/`, `scripts/`, `contract/`)
- **Worktree setup**: `npm ci --ignore-scripts`
- **Checks** (copied from `.github/workflows/container.yml`, jobs `test`, `contract`, `image`, in order):
  - `npm run check:deps`
  - `npm run typecheck`
  - `npm run lint`
  - `npm run build`
  - `npm run openapi && test -z "$(git status --porcelain -- openapi.json)"`
  - `TEST_MYSQL_HOST=127.0.0.1 TEST_MYSQL_PORT=3306 npm test` (unverified locally: needs MySQL 9 on :3306 as CI's service provides; docker daemon was not running. Without it 2 MySQL suites fail, and `writes.test.ts` hit one ECONNRESET on Windows that CI does not show)
  - `docker build -t agent-service:contract .` (unverified locally: docker daemon not running)
  - `cd contract && npm ci --ignore-scripts && npm run typecheck`
  - `CONTRACT_IMAGE=agent-service:contract CONTRACT_MYSQL_HOST=host.docker.internal CONTRACT_MYSQL_PORT=3306 CONTRACT_MYSQL_USER=root CONTRACT_MYSQL_PASSWORD=example CONTRACT_MYSQL_DATABASE=vnm-agent-db node scripts/run-contract.cjs` (unverified locally: needs the image and MySQL)
  - `docker buildx build --platform linux/arm64 .` (unverified locally: docker daemon not running; CI job `image`, PRs only)
  - CI also runs `npm audit --audit-level=high` after `check:deps`; it is red on main (V-M-Pioneer-Trading/meta#119) and left out here by owner decision until that ticket closes, so CI on a PR is red for that step alone.
- **Checks verified on main**: 0502eba 2026-10-28
- **Coding standards**: `@v-m-pioneer-trading/eslint-config` base (`package.json:34`, `eslint.config.mjs:8`); invariants in `CLAUDE.md`
- **Risk areas** (validator reviews diffs touching these on Opus):
  - `src/auth.ts` route table (`:22-44`): every route's gate. `GET /api/agent/v1/contracts/:id/deliveries` and `GET /api/agent/v1/transactions` are unauthenticated by design (`:42-43`)
  - Money: `POST ships/purchase`, `ships/:s/purchase|sell`, `contracts/:id/accept|fulfill` → `src/gateway/client.ts:103-131`; automation-service calls them with no human in the loop
  - `src/db/**`: `migrate.ts` runs on every boot against production MySQL
  - `contract/**`: the parity oracle; never edited to make code pass (`CLAUDE.md:9-10`)
  - `allowed-dependencies.txt`, `dependency-snapshot.txt`, `scripts/check-dependencies.cjs`: the dependency gate
  - `.github/workflows/container.yml`: a merge to main deploys to production (job `docker`, SSM send-command `:290-330`); job names `test`, `image`, `contract` are required checks, a rename blocks every merge
- **Contracts** (see team-modes **Contract changes**):
  - API: `openapi.json` (generated by `npm run openapi`) · provider agent-service; mirrored to `../meta/openapi/agent-service.json` by `sync-openapi`. Consumers: command-interface, fleet-service (`POST contracts/:id/deliveries`), automation-service
  - Consumed: st-gateway /proxy (`src/config.ts:234`) · provider st-gateway; auth-service introspection via clerk-client · provider auth-service; scope literal `fleet:control` (`src/auth.ts:15`) · provider auth-service (auth-design decision 2)
  - Vendored: `contract/fixtures/gateway-errors.json`, copy of `../meta/fixtures/gateway-errors.json` (line 2 differs on purpose), pinned in `contract/fixtures/SOURCE.txt` · provider meta; a provider change means a re-vendor here
  - Shared packages: clerk-client 2.0.1 tarball (`package.json:24`) · provider clerk-client; eslint-config 1.1.0 (`package.json:34`) · provider eslint-config
  - Infra outputs: SSM document `agent-service-bootstrap-<instance>` and the agent-service stack · provider infrastructure (`../V-M-Pioneer-Trading_infrastructure/agent-service/`)
